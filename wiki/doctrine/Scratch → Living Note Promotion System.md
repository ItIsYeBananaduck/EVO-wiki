# Scratch → Living Note Promotion System

## Core Principle

A note becomes living when it proves value over time.

Promotion is based on usage, not creation.

## Promotion Signals

A Scratch is promoted when at least 2 signal categories are met.

### 1. Reuse

- opened multiple times
- referenced repeatedly

### 2. Connection

- linked to other notes
- linked to tasks or methods

### 3. Expansion

- grows in size
- gains structure such as headings or lists

### 4. Context Importance

- tied to active task or project
- used in decisions

## Promotion Rule

Promote when 2 or more signal categories are active.

## Promotion Types

### Suggested

Alice prompts the user to promote.

### Automatic

High-confidence notes are promoted automatically.

### Manual

User explicitly promotes.

## After Promotion

- Type is assigned
- Domain is assigned
- Tags are inferred
- relationships are enabled
- note enters system reasoning

## Anti-Promotion Rules

Do not promote:

- very short notes
- link-only notes
- temporary notes
- unused notes

## Lifecycle

Scratch:

Create → Use → Ignore

Living Note:

Create → Expand → Link → Evolve → Reuse

## System Impact

Scratches:

- ignored by reasoning

Living Notes:

- used by Alice
- used by Connect
- feed system intelligence

## Evolution Path

Scratch → Living Note → Method → Talent
