# EVOconnect — Mobile Operational Continuity (Raw Draft)

## Purpose

This note defines the architectural role of Connect on mobile devices.

Mobile Connect is not intended to function as:
- a full desktop workspace
- a pane orchestration environment
- a desktop window management system
- a full Command Center replacement

Desktop Connect and Mobile Connect serve different operational purposes.

Desktop Connect is:
- orchestration-focused
- workspace-focused
- pane-focused
- workflow-construction-focused

Mobile Connect is:
- continuity-focused
- delegation-focused
- lightweight-intervention-focused
- operational-awareness-focused

The goal of Mobile Connect is to allow users to remain connected to their operational ecosystem from anywhere without recreating the complexity of the desktop workspace environment on a phone.

---

# Core Principle

Desktop Connect builds workflows.

Mobile Connect maintains continuity with workflows.

The phone is not intended to become the primary orchestration environment.

The phone is intended to become:
- a persistent operational access layer
- a lightweight workflow surface
- a delegation surface
- an awareness surface
- a remote intervention surface

---

# Mobile Philosophy

Mobile Connect should prioritize:
- simplicity
- continuity
- speed
- awareness
- delegation
- retrieval
- lightweight interaction

It should avoid:
- desktop complexity
- dense pane orchestration
- heavy multitasking systems
- floating workspace management
- complex desktop interaction patterns

The mobile experience should feel lightweight while remaining deeply connected to the larger EVO ecosystem.

---

# Relationship to Desktop Connect

Desktop Connect remains the primary orchestration environment.

Desktop Connect handles:
- pane composition
- workflow construction
- heavy orchestration
- grouped panes
- complex workspace management
- advanced workflow persistence
- resource orchestration
- external app orchestration

Mobile Connect complements this system rather than replacing it.

---

# Alice Role Difference

Alice serves different roles across the EVO ecosystem.

This distinction is extremely important.

---

# Alice in EVOtraining, EVOmind, and EVOlearn

In EVOtraining, EVOmind, and EVOlearn:

Alice is:
- the primary interaction surface
- the primary conversational layer
- emotionally central
- visually prominent
- foundational to the user experience

These apps are fundamentally Alice-centric experiences.

The user primarily interacts through Alice.

---

# Alice in Desktop Connect

Desktop Connect is different.

Desktop Connect is:
- workspace-centric
- workflow-centric
- orchestration-centric

The primary focus is:
- the workspace
- the workflow
- the user’s operational environment

Alice is deeply integrated into the workspace but is not the central focus of the experience.

Alice acts as:
- an assistant
- a collaborator
- a delegation layer
- a workflow helper
- a contextual orchestration layer

Users should be able to:
- use Connect manually
- use Connect partially with Alice
- use Connect heavily with Alice
- use Connect with Alice mostly inactive

Desktop Connect must remain fully functional even when Alice is minimally active.

---

# Alice in Mobile Connect

Mobile Connect shifts Alice back toward the foreground.

This happens naturally because mobile workflows are more delegation-oriented.

On mobile, users are typically:
- checking workflow state
- reviewing tasks
- retrieving information
- delegating actions
- approving workflows
- asking for status updates
- interacting conversationally

As a result:
- Alice becomes more visually present
- Alice becomes more interaction-central
- delegation becomes a core interaction pattern

This does not mean Mobile Connect becomes identical to EVOtraining or EVOmind.

The difference is:
- Mobile Connect remains operationally focused
- Alice is facilitating operational continuity rather than coaching or emotional interaction

---

# Operational Continuity

Mobile Connect exists to preserve operational continuity across the Hive.

Users should be able to:
- view active tasks
- view active workflows
- see what Alice is doing
- review workflow status
- receive approval requests
- access notes
- access files
- access the Connect Library
- retrieve workspace context
- remotely interact with workflows

without needing the full desktop orchestration environment.

---

# Hive Awareness

Mobile Connect should remain aware of:
- active devices
- active workflows
- suspended workflows
- workflow ownership
- current execution state
- current Space
- current operational context

The user should feel connected to the larger ecosystem even while away from the primary workstation.

---

# Space Awareness

Mobile Connect should remain deeply Space-aware.

Examples:
- Life Space
- Work Space
- Development Space
- Research Space

The active Space should influence:
- visible tasks
- visible workflows
- notifications
- shortcuts
- quick actions
- Alice context
- approval requests

This allows the mobile experience to remain contextually focused rather than overwhelming.

---

# Mobile Connect Library

The Connect Library remains one of the most important systems on mobile.

Mobile users should still have access to:
- files
- notes
- folders
- tasks
- workflows
- repos
- connected storage
- operational retrieval

The goal is not full workspace construction.

The goal is operational access and retrieval.

---

# Mobile Tasks and Notes

Tasks and Notes are core mobile interaction systems.

Mobile users should be able to:
- create tasks
- update tasks
- review task state
- capture quick notes
- access Living Notes
- create scratches
- retrieve operational context
- quickly communicate with Alice about workflows

These systems should remain lightweight and fast.

---

# Remote Delegation

Mobile Connect should strongly support delegation workflows.

Examples:
- “Alice, finish this task.”
- “Alice, summarize what changed.”
- “Alice, check the current workflow state.”
- “Alice, reopen my workspace when I get home.”
- “Alice, remind me about this workflow later.”

Mobile interaction should emphasize:
- delegation
- retrieval
- lightweight intervention

rather than heavy orchestration.

---

# Enterprise and Scoped Access

Mobile Connect must support scoped operational visibility.

This is especially important in enterprise environments.

The user’s Alice remains personal and persistent across EVO systems.

However:
- enterprise Spaces are permission-scoped
- proprietary information remains enterprise-owned
- enterprise access must remain enforceable across devices

Mobile devices should only expose:
- workflows
- tasks
- files
- notes
- operational context

that the user and device are currently entitled to access.

---

# Device Awareness

Alice should remain aware of:
- the current device
- device capability
- device role
- device ownership
- operational context

Examples:
- home desktop
- work laptop
- personal phone
- company phone
- tablet
- remote node

Different devices may expose different:
- Spaces
- workflows
- permissions
- orchestration capabilities
- interaction models

---

# Pane Philosophy on Mobile

Pane systems should remain heavily simplified on mobile.

The desktop pane orchestration model should not be directly recreated on phones.

Mobile may still expose:
- lightweight temporary surfaces
- contextual cards
- quick-action panes
- lightweight overlays

But mobile should avoid:
- complex pane composition
- heavy floating workspace systems
- desktop-style window orchestration

The mobile experience should remain fast and intuitive.

---

# Long-Term Direction

The long-term goal is for Mobile Connect to become:

- a persistent operational companion
- a lightweight delegation surface
- a workflow continuity layer
- a remote operational access system
- a Hive awareness surface

The larger idea is simple:

Desktop Connect builds and orchestrates workflows.

Mobile Connect keeps the user connected to them from anywhere.
