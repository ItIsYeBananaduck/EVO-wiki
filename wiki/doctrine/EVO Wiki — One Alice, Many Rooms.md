# Purpose

Define the shared EVO Wiki architecture for Alice across EVOtraining, EVOmind, EVOlearn, and EVOconnect.

This wiki is inspired by Karpathy-style markdown memory, but it is adapted for EVO's multi-app architecture.

The goal is not four separate memories.

The goal is one Alice moving through many rooms.

# Core Principle

One Alice.

One root wiki index.

Four domain branches.

Cross-app synthesis over time.

Alice has access to the full EVO Wiki map, but she normally loads only the branch relevant to the app she is currently operating in.

# One Alice, Many Rooms

Alice is the same intelligence across the EVO ecosystem.

Each app is a room:

- EVOtraining is the physical stress room.
- EVOmind is the emotional stress room.
- EVOlearn is the cognitive stress room.
- EVOconnect is the environment and intervention room.

The root wiki is the hallway connecting those rooms.

# Domain Signal Model

EVOtraining logs = physical stress signals.

EVOmind logs = emotional stress signals.

EVOlearn logs = cognitive stress signals.

EVOconnect = environment adjustment and intervention orchestration.

Each domain has its own raw files, logs, summaries, Alice Journal entries, and wiki pages.

The branches are separate enough to preserve domain boundaries, but connected enough to allow Alice to learn cross-app trends.

# EVOtraining Branch

EVOtraining captures physical stress and physical adaptation.

It may include:

- workouts
- sets, reps, load, rest, RPE
- readiness
- soreness
- pump
- fatigue
- sleep and recovery impact
- performance trends
- mesocycle summaries
- user response patterns

The EVOtraining branch answers:

How is the body responding?

# EVOmind Branch

EVOmind captures emotional stress and how the body reacts to emotional stress.

It may include:

- emotional stress logs
- mood shifts
- intensity and duration of stress states
- emotional recovery patterns
- conversational journal entries
- Alice Journal entries
- reflection summaries
- user-specific emotional load patterns

The EVOmind branch answers:

How is the emotional system responding?

EVOmind logs are not weaker than training logs. They are a different signal class.

They help Alice learn how emotional stress affects the user's body, recovery, attention, and behavior.

# EVOlearn Branch

EVOlearn captures cognitive stress and learning load.

It may include:

- learning session logs
- comprehension signals
- frustration signals
- cognitive fatigue
- attention drift
- concept mastery
- study rhythm
- learning summaries
- knowledge gaps

The EVOlearn branch answers:

How is the cognitive system responding?

# EVOconnect Branch

EVOconnect uses what Alice learns from the other rooms to reduce friction in the user's environment.

It may include:

- task logs
- workflow summaries
- Method history
- Talent history
- user approval patterns
- automation outcomes
- environment friction patterns
- stress intervention patterns

The EVOconnect branch answers:

What can be changed in the user's environment or workflow to reduce load?

# Cross-App Synthesis

Cross-App Synthesis contains patterns that are useful across more than one app.

Examples:

- emotional stress suppresses physical recovery
- cognitive fatigue predicts training adherence drops
- workload spikes predict poor sleep or skipped workouts
- poor sleep amplifies both physical and emotional stress
- repeated task friction increases emotional load

Cross-app synthesis should be careful, scoped, and privacy-aware.

It should not casually expose source material from sensitive domains.

# Cross-App Privacy Rule

Alice may use cross-app patterns, but she should not expose private source details unless the user explicitly asks or the current app has permission.

Bad:

You journaled about relationship stress last night, so I am lowering your leg volume.

Good:

Your recovery signals look a little fragile today. Let's keep progression optional.

Same intelligence. Safer presentation.

# Retrieval Rule

Alice should normally retrieve memory in this order:

1. Current app branch
2. Current task/session context
3. Relevant domain wiki pages
4. Recent domain summaries
5. Cross-App Synthesis, if useful
6. Root Index, if navigation is unclear
7. Embedded chat history, only for fuzzy conversational recall
8. Raw logs, only for investigation or out-of-pattern analysis

# Wiki vs Embeddings

Embedded chat history helps Alice answer:

Have we talked about this before?

The EVO Wiki helps Alice answer:

What do we now understand to be true?

Embeddings are a recall tool.

The wiki is structured memory.

# Wiki vs Adapters

The wiki stores explicit knowledge.

Adapters learn interpretation bias.

The wiki remembers what happened.

Adapters help Alice understand what it probably means.

# Relationship to Connect Behavior

EVOconnect does not own the wiki.

EVOconnect uses the shared wiki to identify when environmental intervention may reduce stress or friction.

Connect's behavior layer is separate from the shared memory spine.

The wiki informs Connect.

Methods and Talents govern execution.

# Relationship to EVOLoRA Mesh

The EVOLoRA Mesh does not own the wiki.

The Mesh consumes wiki-derived signals and structured summaries to improve adapter relevance and interpretation.

The wiki stores explicit memory.

The Mesh interprets through scoped lightweight adapters.

Alice decides.

# Final Principle

The EVO Wiki is not four separate app memories.

It is one shared root-indexed memory system.

Alice normally operates inside one room at a time, but over time she can learn how signals from every room affect the whole person.

This is the memory spine for One Alice, Many Rooms.
