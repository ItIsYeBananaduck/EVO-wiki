# EVOS1-273 — Shared Vector Memory Boundaries and Indexing Policy

## Purpose

Define a strict, shared policy for what enters vector memory across the **entire EVO cognition layer** (EVOtraining, EVOmind, EVOlearn, EVOconnect), not just journals or training artifacts.

This policy aligns with `/docs/evonotes/` doctrine: vector memory indexes cognition artifacts with explicit boundaries, not raw system exhaust.

- ✅ In scope: cognition-wide embedding allow/deny rules, required pre-embedding summarization, journal strategy, context/domain signal handling, dedupe/rate controls.
- ❌ Out of scope: model/provider selection, vector DB vendor configuration, retrieval ranking implementation.

---

## Policy Goals

1. Ensure only cognition-relevant artifacts are embedded across all cognition streams.
2. Minimize token and storage usage while preserving retrieval quality.
3. Prevent blind indexing of raw logs, transport events, and unapproved material.

export type IndexDecision = 'index' | 'skip' | 'quarantine';

## Inclusion Rules (Allowlist First)

### Allowed for Embedding

1. **Approved journal entries** (`artifact_type = journal_entry`, `approved = true`)
2. **Stable interpreted observations** (not transient diagnostics)
3. **User preference statements** with behavioral relevance
4. **Finalized plan decisions/outcomes**
5. **Context snapshots** that capture stable cognitive state (goal/constraint/intent snapshots)
6. **Domain signals** that are transformed into cognition-relevant summaries (not raw event streams)

### Conditionally Allowed

- `journal_summary` may be indexed as a companion memory object when generated by approved summarization rules and linked to a parent journal entry.
- `context_snapshot` and `domain_signal` entries are indexable only after summarization/normalization and policy checks.

### Explicitly Excluded (Hard Deny)

1. **Raw logs** (`artifact_type = raw_log`) — never embedded.
2. **Transport/system events** (`artifact_type = transport_event`) — never embedded.
3. **Unapproved drafts** (`artifact_type = draft_unapproved`) — never embedded.
4. **Diagnostic traces/stack output** — never embedded.
5. **Unbounded context dumps** (prompt transcripts, middleware payload mirrors) — never embedded directly.

### Default Rule

If an artifact is not explicitly allowlisted, decision = `skip` with reason `not_allowlisted`.

## Summarization Requirements Before Embedding

For all long-form or high-volume artifacts (`journal_entry`, `observation`, `plan_decision`, `context_snapshot`, `domain_signal`):

1. **Normalization required**
   - remove transport/debug boilerplate,
   - remove duplicate whitespace/noise,
   - preserve semantics and key entities.

2. **Length gating**
   - If normalized text exceeds configured threshold (recommended: > 800 tokens), create a faithful summary and embed:
     - one summary vector,
     - plus bounded detail chunks (max 3) only when needed for retrieval fidelity.

3. **Faithfulness requirement**
   - Summaries must not introduce facts.
   - Summary must retain: actor, action, outcome, timeframe.

4. **Metadata required on every embedded row**
   - Required: `source_ref`, `artifact_type`, `app_domain`, `created_at`.
   - Recommended: `version`, `summary_level`, and parent/child linkage IDs.

---

## Journal Embedding Strategy

For each approved journal entry:

1. Generate and index a **primary summary embedding**.
2. Optionally index **detail chunks** only if above long-form threshold.
3. Store relation links:
   - `journal_entry_id -> summary_vector_id`
   - `journal_entry_id -> chunk_vector_ids[]`
4. At retrieval time, prioritize summary vectors first; expand to chunks only when confidence is low or detail intent is detected.

This keeps recall high while controlling token and index growth.

---

## Context and Domain Signal Strategy

1. Convert context and domain signal artifacts into bounded cognition summaries before indexing.
2. Reject pass-through ingestion of raw event feeds.
3. Enforce TTL/refresh windows for volatile context snapshots to avoid stale over-indexing.
4. Re-index only on meaningful semantic change, not every sync tick.

---

## Anti-Over-Indexing Controls

1. **Deduplication**
   - Compute semantic/content fingerprint.
   - Skip if near-duplicate already indexed within same user + artifact family window.

2. **Rate limits per user/day**
   - Hard cap new vectors/day (configurable by artifact type).
   - Overflow candidates go to `quarantine` for deferred review.

3. **Change-threshold indexing**
   - Re-embed only if meaningful delta exceeds threshold (semantic diff gate).

4. **Priority budget allocation**
   - Priority order: journal summaries > context snapshots > domain signals > observations > plan decisions.
   - Lower-priority classes are dropped first when budget is exhausted.

5. **Audit logging**
   - Every `skip`/`quarantine` decision must include machine-readable reason codes.

## Acceptance Criteria Mapping

- **Clear embedding policy exists**: explicit cognition-wide allow/deny/default behavior.
- **Token usage minimized**: summary-first strategy + length gating + per-day vector caps.
- **No blind indexing occurs**: allowlist-first + hard denials + audit reason codes + quarantine path.
