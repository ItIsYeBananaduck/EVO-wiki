
## Core Idea

> Notes are not documents.  
> Notes are structured reflections of thinking, captured through conversation.

EVOconnect introduces:

> **Conversational, multi-level, context-aware notes**

Notes are:
- created through interaction with Alice  
- automatically categorized  
- accessible across all levels of the system  
- dynamically connected to tasks, projects, and execution  

---

## Hierarchical Structure

Notes exist across multiple levels of abstraction:

### 1. Lifespace Notes (Global)

- broad, unstructured thinking  
- whiteboard-style ideas  
- cross-project concepts  
- personal reflections  

Characteristics:
- high ambiguity  
- low structure  
- exploratory  

---

### 2. Workspace Notes (Global Operational)

- system-wide planning  
- multi-project coordination  
- high-level strategy  

Examples:
- beta planning  
- marketing direction  
- system-wide decisions  

---

### 3. Project Notes

- tied to a specific project  
- more focused than global notes  
- still flexible and exploratory  

Examples:
- EVOtraining marketing ideas  
- Connect architecture notes  
- feature discussions  

Accessible from:
- project view  
- global notes  

---

### 4. Phase Notes

- tied to a project phase  
- time-bound and goal-oriented  

Examples:
- beta phase notes  
- monorepo migration notes  
- launch preparation  

Characteristics:
- more structured  
- tied to current objectives  

---

### 5. Task & Subtask Notes

- directly tied to execution  
- contextual to a specific task  

Examples:
- bug investigation notes  
- implementation decisions  
- test observations  

Characteristics:
- highly specific  
- execution-focused  

---

## Key Principle — Cross-Level Accessibility

> Notes are not siloed.

Every note can be:

- accessed from its native level  
- surfaced in higher or lower levels  
- referenced across contexts  

Example:

A note created in a task:
- is visible in the task  
- appears in the phase  
- is accessible in the project  
- can be referenced globally  

---

## Conversational Note Creation

### Core Behavior

From any chat, the user can say:

- “Save this as a note”
- “Add this to project notes”
- “This belongs to beta phase”
- “Attach this to this task”

Alice will:

1. classify the note level  
2. tag it appropriately  
3. link it to relevant entities  
4. store it in the correct structure  

---

## Automatic Tagging & Classification

Alice determines:

- level (lifespace, workspace, project, phase, task)  
- related entities (project, task, phase)  
- topic/category  
- relevance  

User can override at any time.

---

## Notes as First-Class System Objects

Notes are not passive.

They can:

- attach to tasks  
- inform Methods  
- contribute to Talent creation  
- be referenced during execution  
- influence decision-making  

---

## Relationship to Task System

Notes connect directly to tasks:

- every task can have notes  
- every subtask can have notes  
- notes can evolve into tasks  

Example flow:

conversation → note → structured note → task → execution  

---

## Relationship to Training Mode

Notes can become:

- Method definitions  
- training references  
- context for Talent creation  

Training Mode can use notes as:
- source material  
- structured guidance  

---

## Relationship to Delegator

Notes do not grant execution rights.

Even if a note describes an action:

- it must still become a Method  
- must still be approved  
- must still pass Delegator  

---

## UX Philosophy

> This is not a notes app.  
> This is a thinking system.

Users should feel like:

- they are talking to Alice  
- ideas are being captured naturally  
- structure emerges automatically  
- nothing is lost  

---

## Key Behaviors

### 1. Capture without friction
User does not need to:
- decide structure first  
- choose location manually  

---

### 2. Structure emerges over time
Alice:
- organizes  
- links  
- surfaces relevant notes  

---

### 3. Context is preserved
Every note retains:
- origin context  
- related entities  
- conversation history  

---

### 4. Notes evolve into execution
Notes are not static.

They can become:
- tasks  
- Methods  
- Talents  

---

## Example Flow

User (chat):
> “We should do a vignette campaign where each clip reveals more over time”

Alice:
- recognizes concept  
- creates project-level note under EVOtraining  
- tags as marketing  

Later:

User:
> “Turn that into something actionable”

Alice:
- breaks into tasks  
- creates execution plan  
- links back to original note  

---

## Core Takeaway

> Notes are the bridge between thinking and execution.

They begin as:
- unstructured conversation  

They become:
- structured knowledge  

And eventually:
- actionable work  

All without forcing the user to change how they think.
