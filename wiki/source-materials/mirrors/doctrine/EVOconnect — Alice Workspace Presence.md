# EVOconnect — Alice Workspace Presence (Raw Draft)

## Purpose

This note defines how Alice exists inside the Connect workspace.

Alice is not intended to function as:
- a floating chatbot
- a sidebar assistant
- a notification system
- a disconnected AI overlay

Alice is intended to function as the persistent cognitive layer of the Connect workspace.

The goal is for Alice to feel:
- present
- aware
- contextual
- operationally integrated
- lightweight
- non-intrusive
- continuously available

without overwhelming the user or disrupting workflows.

---

# Core Principle

Alice exists across the workspace, not inside a pane.

Alice may interact with panes, views, Spaces, workflows, and operational systems, but she is not confined to any one interface surface.

This is important because Connect is intended to function as a living workspace environment.

Alice is the persistent awareness layer across that environment.

---

# Alice as a Cognitive Presence

Alice should feel less like:
- launching an assistant
- opening a chatbot
- switching to an AI app

and more like:
- working alongside a persistent cognitive partner
- interacting with an operationally aware workspace
- remaining connected to ongoing workflows

The user should feel that Alice understands:
- what they are doing
- what they were doing
- what workflows are active
- what tasks matter right now
- what operational context is currently relevant

without needing to constantly restate context.

---

# Persistent Presence

Alice should remain present across:
- Spaces
- Modes
- Views
- Panes
- workflows
- resource transitions

Alice should not feel like she disappears simply because:
- a pane collapsed
- a workflow suspended
- a view hibernated
- the user switched modes

The workspace may change shape around the user, but Alice should feel continuous across those transitions.

---

# Relationship to Modes

Alice behaves differently depending on the active mode.

---

## Pane Mode

In Pane Mode, Alice acts as:
- a lightweight assistant presence
- a contextual workflow companion
- a passive awareness layer

Alice should remain:
- lightweight
- accessible
- movable
- non-intrusive

She may:
- surface lightweight updates
- expose workflow state
- surface approvals
- monitor lightweight workflows
- remain contextually aware

Pane Mode prioritizes subtle presence over heavy orchestration.

---

## Command Center Mode

In Command Center, Alice acts as:
- an operational coordinator
- workflow orchestrator
- task-aware assistant
- resource-aware assistant
- workspace-aware assistant

This is where Alice’s orchestration role becomes most visible.

Alice may:
- coordinate workflows
- assist coding tasks
- manage operational context
- surface task progress
- negotiate resource usage
- coordinate panes and workflows
- interact with multiple systems simultaneously

Command Center is where Alice becomes deeply integrated into the workspace itself.

---

## HUD Mode

In HUD Mode, Alice acts as:
- a lightweight persistent presence
- a quick interaction layer
- a notification surface
- an awareness layer

HUD Mode should allow users to:
- quickly interact with Alice
- receive operational updates
- approve workflows
- check ongoing status
- re-enter deeper workspace states

without requiring the full workspace to remain visible.

---

# Relationship to Spaces

Alice should remain aware of the active Space.

Different Spaces may shift:
- Alice priorities
- workflow focus
- suggested actions
- visible operational state
- relevant context
- available workflows

Examples:
- Development Space biases toward implementation workflows
- Research Space biases toward information gathering
- Life Space biases toward reminders and organization

Alice should adapt naturally without requiring explicit context resets from the user.

---

# Relationship to Views

Alice should remain aware of:
- active views
- grouped panes
- active workflows
- pane composition
- current operational goals

Different views may influence:
- active task context
- visible operational state
- workflow suggestions
- active tools
- contextual chat continuity

This allows Alice to feel deeply integrated into workflow environments rather than disconnected from them.

---

# Relationship to Panes

Alice may interact with any pane.

Examples:
- Tasks
- EVOterminal
- EVOcode
- EVObrowser
- Notes
- Git
- Connect Library

Alice should understand:
- which panes are active
- which panes are collapsed
- which panes are suspended
- which panes are important to the current workflow

This allows Alice to maintain contextual continuity even when the workspace changes shape.

---

# Movable Presence

Alice should not feel physically obstructive.

The user should be able to:
- move Alice
- reposition Alice
- allow automatic repositioning
- minimize Alice visibility
- reduce presence intensity

Alice may eventually:
- avoid overlapping important UI
- intelligently reposition
- remain visible without obstructing workflows

The goal is to make Alice feel naturally integrated into the workspace rather than glued on top of it.

---

# Non-Intrusive Design

Alice should avoid:
- excessive popups
- disruptive overlays
- constant interruptions
- aggressive notifications
- unnecessary visual noise

Most Alice communication should happen through:
- lightweight status surfaces
- Action Bar visibility
- mini action bars
- subtle workflow indicators
- contextual approvals

Alice should feel operationally present without constantly demanding attention.

---

# Workflow Awareness

Alice should continuously remain aware of:
- active workflows
- dormant workflows
- workflow transitions
- approval requirements
- ongoing tasks
- resource pressure
- operational priorities

This awareness allows Alice to:
- maintain continuity
- reduce repeated explanations
- coordinate workflows intelligently
- surface relevant context automatically

---

# Contextual Chat Continuity

Alice chat should feel connected to the active workflow environment.

Examples:
- opening development panes may restore development context
- opening research workflows may restore research context
- opening task workflows may restore operational context

The goal is to avoid making the user repeatedly explain:
- what they are doing
- what workflow they are in
- what task is active

Alice should use workspace state to maintain continuity naturally.

---

# Approval Surfaces

Alice should surface approvals contextually.

Examples:
- Action Bar
- mini action bars
- HUD notifications
- lightweight prompts
- operational surfaces

Approvals should feel:
- lightweight
- contextual
- workflow-aware

rather than disruptive modal interruptions whenever possible.

---

# Resource-Aware Presence

Alice should remain aware of system resources.

During resource pressure:
- heavier workflows may suspend
- views may hibernate
- panes may collapse

but Alice should remain:
- operationally aware
- contextually present
- lightly available

The workspace may shrink, but Alice should still feel present.

---

# Alice During Background Workflows

Alice may continue lightweight workflows while the user does other things.

Examples:
- monitoring a task
- running a command
- waiting for approval
- gathering information
- preparing summaries

The user should still be able to:
- check workflow state
- see progress
- intervene if necessary
- approve actions
- reopen workflows quickly

without keeping the entire workspace visible.

---

# Emotional Design Philosophy

Alice should feel:
- supportive
- aware
- helpful
- operationally intelligent
- calm
- continuously available

Alice should not feel:
- demanding
- noisy
- intrusive
- overwhelming
- attention-seeking

The workspace should feel calmer and more coordinated because Alice exists within it.

---

# Long-Term Direction

The long-term goal is for Alice to feel less like:
- an application
- a chatbot
- a tool

and more like:
- a persistent cognitive workspace layer
- an operational coordinator
- a contextual workflow companion
- an adaptive presence integrated into the workspace itself

The larger idea is simple:

The workspace changes shape around the user.

Alice remains continuously aware across all of it.
