#connect
## Core Idea

> Alice only learns workflows when explicitly invited.

There is **no passive observation**.

Users must enter:

> **Talent Training Mode**

to teach Alice how to perform a task.

---

## Why This Exists

### Privacy First

- No silent tracking  
- No background learning  
- No hidden behavior  

Alice does not:
- watch user activity
- infer behavior without consent
- record workflows automatically

---

## Core Principle

> **Learning requires intent.**

The user must explicitly say:
> “Teach Alice this.”

---

## Talent Training Flow

### Step 1 — Enter Training Mode

User activates:
- “Train a Talent”
- or similar entry point

Clear UI state change:
- visual indicator (recording/training)
- explicit awareness that Alice is learning

---

### Step 2 — User Performs Task

User completes the workflow manually:
- navigation
- inputs
- actions
- outcome

Alice:
- observes only within this mode
- records actions and intent
- does not act independently

---

### Step 3 — Alice Builds Method

After completion, Alice generates:

> **A Method = step-by-step reproducible workflow**

---

### Step 4 — Method Review (Required)

Alice presents:

- What the Talent does  
- Step-by-step method  
- Tools required  
- Permissions needed  
- Data involved  
- Expected outcome  

In simple, non-technical language.

---

### Step 5 — Permission Requests

Alice explains:

> “To do this for you, I need access to…”

User explicitly approves or denies.

---

### Step 6 — User Approval

User chooses:
- Approve Talent  
- Modify Method  
- Reject  

No automatic creation.

---

### Step 7 — Talent Created

Once approved:
- Talent becomes reusable  
- Bound to Method  
- Governed by Delegator  
- Executed through Task system  

---

## Key Principles

### 1. No Silent Learning

> If the user did not enter Training Mode, Alice did not learn.

---

### 2. Explicit Awareness

User always knows:
- when learning is happening  
- what is being learned  

---

### 3. Method Transparency

Every Talent must be:
- explainable  
- reviewable  
- editable  

---

### 4. Permission Clarity

No hidden access:
- all required capabilities must be approved  
- reasons must be explained  

---

### 5. User Control

- User initiates learning  
- User approves output  
- User owns the result  

---

## Relationship to Headless Usability

Training Mode enables:

- non-technical users to create automation  
- without coding  
- without configuration  

By simply:
> doing the task once

---

## Relationship to Talent Sharing

Because Talents are:
- intentionally created  
- method-based  
- reviewed  

They are safe to share if:
- method is visible  
- permissions are clear  
- receiving user re-approves  

---

## UX Requirements

- Training Mode must be clearly visible and distinct  
- Must feel safe and intentional  
- Must not feel like surveillance  
- Must be easy to start and stop  
- Must summarize clearly after completion  

---

## Core Takeaway

> Alice does not learn by watching.  
> She learns by being taught.

Training Mode ensures:
- privacy  
- trust  
- control  

while still enabling powerful automation.
