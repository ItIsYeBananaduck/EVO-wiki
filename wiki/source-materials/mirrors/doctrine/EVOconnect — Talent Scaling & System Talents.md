#connect

## Core Reality

> Plugins are cheap.  
> Talents are expensive.

Every new plugin introduces:
- new capabilities
- new workflows
- new edge cases

Which means:

> Every plugin requires a set of high-quality, prebuilt Talents.

---

## Why System Talents Are Required

Without system Talents:

- Users must teach everything manually  
- Connect feels incomplete  
- Tool abstraction breaks  
- Adoption drops  

---

## System Talents Definition

> System Talents are prebuilt, first-party Talents shipped with a plugin.

They represent:

- common workflows  
- best practices  
- safe defaults  

---

## Example — QuickBooks Plugin

System Talents might include:

- Create invoice  
- Send invoice  
- Track expense  
- Generate report  
- Categorize transaction  

---

## Core Principle

> A plugin is not complete until it has usable Talents.

---

## The Scaling Problem

If you manually create Talents for every plugin:

- effort increases linearly (or worse)
- maintenance becomes painful
- consistency becomes difficult

---

## The Solution — Layered Talent Strategy

---

## 1. Core System Talents (Handcrafted)

- Built by you
- High quality
- Fully tested
- Cover most common use cases

These are:

> “out-of-the-box magic”

---

## 2. Template-Based Talents (Semi-Automated)

Instead of building everything from scratch:

- define reusable patterns like:
  - Create entity  
  - Update entity  
  - Send/submit  
  - Fetch/report  

Then map them to plugin capabilities.

---

## 3. AI-Assisted Talent Generation

Use Alice herself to:

- propose Talents based on plugin schema  
- generate Methods  
- suggest system Talents  

You review and approve.

---

## 4. User-Created Talents

- Training Mode  
- Repetition learning  
- Task awareness  

This fills the long tail.

---

## 5. Shared Talents (Future)

- peer-to-peer  
- trust-based  
- method-visible  

---

## Coverage Model

You don’t need:

> 100% of workflows prebuilt

You need:

> 60–80% coverage of common use cases

The rest is:
- discovered
- learned
- shared

---

## Plugin Launch Checklist

A plugin is “ready” only if:

- it exposes capabilities  
- it has at least X system Talents  
- those Talents are:
  - tested  
  - understandable  
  - safe  

---

## Maintenance Strategy

System Talents must be:

- versioned  
- updateable  
- backward-compatible  

---

## Key Insight

> You are not building integrations.  
> You are building usable outcomes.

---

## Core Takeaway

> Connect scales through Talents, not plugins.

Plugins give Alice the ability.

Talents give users the outcome.
