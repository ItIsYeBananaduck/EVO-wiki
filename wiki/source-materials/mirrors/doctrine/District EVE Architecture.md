# District EVE Architecture
District EVE Architecture (DE)
Role
District EVE (DE) aggregates across multiple schools.
DE operates on: - School Summaries from SE - No student-level data - No class-level identity - No raw telemetry

Data Flow
Student App → TA → SE → DE

Responsibilities
DE: - compares schools within same grade - analyzes district-wide retention trends - identifies systemic template performance patterns - executes district-level Procedures
DE does NOT: - access student identities - access teacher chat content - audit individual classrooms directly - modify pedagogy

Output Types
district retention distribution
grade-wide variance analysis
cross-school comparison charts
template adoption effectiveness
All outputs remain on district-controlled infrastructure.

Deployment
DE runs: - on district server - isolated from LSCT infrastructure - independent from centralized identity systems

Governance Principle
DE verifies systemic efficiency. It does not evaluate individual students.
Human administrators interpret results.
